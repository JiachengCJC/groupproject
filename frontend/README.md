# Market Lens workspace UI

React + TypeScript UI for the Market Lens API. The browser uses same-origin `/api` requests and an HTTP-only session cookie; model provider credentials stay on the server.

## Development

Node.js 22.12 or later is recommended. From this directory:

```sh
npm ci
npm run dev
```

Vite listens on `127.0.0.1:5173` and proxies `/api` to the FastAPI server at `127.0.0.1:8000`. Start the backend separately. Configure models, credentials, local-only policy, storage and workers on the server; the browser reads their safe capability summary from `/api/config`.

```sh
npm run build     # strict type checks + production bundle in dist/
npm run lint      # strict TypeScript checks + formatting verification
npm test          # request, scope, display and decision contract tests
npm run test:e2e  # Playwright browser workflows with mocked API responses
```

The FastAPI application serves the production bundle when `frontend/dist` exists. The root Dockerfile builds and copies this bundle automatically. No runtime Node server is needed in production.

## Browser tests

Install a supported browser with `npx playwright install chromium`, or use the installed Chrome browser:

```sh
PLAYWRIGHT_CHROME_CHANNEL=1 npm run test:e2e
```

The mocked suite covers setup/login, local-only model controls, Local Fast/Quality/Auto routing controls and availability, profile preservation in reruns/revisions/evaluations/schedules, data scope, durable upload polling, analysis/citations/review/export visibility, OpenAI Decisions availability and probability displays, legacy request migration, viewer permissions, evaluation labels, data dictionary, members, schedules, connectors and mobile navigation. Screenshots and the HTML report are written to ignored `test-results/` and `playwright-report/` directories.

A separate integration test can create a test administrator and records on a **disposable local deployment**. It does not run in the default suite:

```sh
E2E_LIVE=1 E2E_BASE_URL=http://127.0.0.1:8003 \
  E2E_ENV_FILE=/private/tmp/market-lens-refactor.env \
  E2E_CREDENTIAL_PATH=/private/tmp/market-lens-qa.json \
  PLAYWRIGHT_CHROME_CHANNEL=1 npm run test:e2e
```

This test reads `SETUP_TOKEN` from the specified deployment environment file, stores only generated test credentials in the specified JSON file (mode 0600), and exercises real setup/login, queued analysis, evidence, approval, PDF/HTML/JSON exports, text upload, persistence and session recovery. Traces are disabled for this test to avoid recording setup credentials. It rejects non-local URLs and does not invoke paid models by default. Setting `E2E_DECISION_MODE=openai_decisions` explicitly enables a paid OpenAI Decisions run and checks the real provider, probability distribution, confidence, and UI interpretation.

Set `E2E_LOCAL_PROFILE=fast`, `quality`, or `auto` to exercise a named local mode against installed Ollama models. This creates a synthetic support-policy document, selects the profile through the UI, and requires an actual Ollama recommendation with the expected policy facts and recorded routing. It cannot be combined with `E2E_DECISION_MODE=openai_decisions`. Local inference may take several minutes. Use an isolated database and deployment; a loopback address alone does not make the instance disposable.

## Local run modes

In **Analysis workspace → Model and analysis settings**, select **Ollama · Local model**, then choose **Local run mode**. Local Fast, Local Quality and Local Auto read their model assignments and server policy from `/api/config`. The UI also checks that every required model is installed, keeps the decision method on **Model recommendation**, and sends `local_profile` without an overriding `model` or a historical server snapshot. **Custom local** retains manual model selection and the existing decision-method options.

The profile card shows configured planning, analysis, image-extraction and document-retrieval roles. Completed analyses show the selected models, routing reason and actual stage assignments. Image extraction is chosen separately during upload. Named profiles are also available in evaluations and scheduled analyses; named-profile evaluations cannot select a cloud judge.

## Structure

- `src/api.ts`, `types.ts`: API boundary, structured errors and shared contracts.
- `src/context.ts`, `App.tsx`: session, capabilities, role permissions and navigation.
- `src/pages/`: analysis, knowledge, history, evaluation and workspace management.
- `src/components/`: reusable dialogs, task polling, tables, charts and dictionary editor.
- `tests/`: browser workflows; `src/contracts.test.ts`: pure contract tests.

All user-provided content is rendered as text. Reports are generated by the backend only after approval. Role controls in the browser reflect server permissions; the API remains the authorization boundary.

All software-authored interface text and accessibility labels are English, with `en-SG` date and number formatting. Uploaded source content remains in its original language. OpenAI Decisions uses the existing server-side OpenAI API key; historical TypeSafe JEV results retain an explicit legacy label, and reruns select OpenAI Decisions. Model choice probabilities are estimates over candidate actions, not business success probabilities.
